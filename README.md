# 케어퐁 (CarePong) 스트레스 감지 모델

키보드·마우스 사용 패턴과 손가락 PPG로 업무 중 스트레스 상태를 감지하는 모델 코드.

데스크톱 펫 서비스 케어퐁의 데이터 분석 파트를 정리한 저장소임. 앱, 백엔드, 수집 서버는 포함하지 않음.

## 배경

- 사무직은 업무가 몰려도 스스로 알아채기 어렵고, 웨어러블을 항상 차고 있지도 않음.
- 케어퐁은 PC에서 늘 발생하는 키보드·마우스 입력으로 "평소보다 몰리는 구간"을 찾아 쉬어가기를 권하는 서비스임.
- 키보드·마우스만으로는 신호가 약해서, 알림이 뜨면 폰 카메라에 손가락을 대고 60초 동안 PPG를 재어 한 번 더 확인하는 구조로 설계함.

## 데이터

| 용도 | 데이터 | 규모 | 공개 여부 |
|---|---|---|---|
| 키보드·마우스 모델 학습 | SWELL-KW (Koldijk et al., 2014) | 25명, 분당 행동 집계 | 공개 데이터셋. 저장소에는 없음 |
| PPG 모델 학습 | MAUS (IEEE DataPort) | 22명, 손가락 PPG, N-back 과제 | 공개 데이터셋. 재배포 제한으로 저장소에는 없음 |
| 키보드·마우스 모델 검증 | 서비스 테스터 대상 직접 수집 | 분석 대상 31명, 유효 라벨 약 157건 | 공개하지 않음 |
| 실행 확인 | 합성 PPG 파형, 예시 입력값 | 8건 | 저장소에 포함 |

- 2026년 10월 서비스 테스트 기간에 모집한 테스터를 대상으로 키·마우스 1분 창과 자가보고(스트레스 여부)를 직접 수집함.
- 수집 원본 194,484행에서 분 단위 중복 제거 후 108,566행, 그중 활동이 있는 창 21,027행을 분석에 씀.
- 인원과 라벨 수는 2026-11-02~03 재추출분 기준임. 초기 10-24 시점에는 23명, 라벨 143건이었음.
- 건강 관련 기록이라 원본과 집계본 모두 올리지 않음. 저장소에 있는 입력값은 전부 합성이거나 예시임.
- 변수 정의와 데이터 점검 내용은 [docs/01_data_and_variables.md](docs/01_data_and_variables.md), [docs/02_data_checks.md](docs/02_data_checks.md)에 있음.

## 방법

### 1. 키보드·마우스 모델

- 입력: 1분 동안의 키 종류별 개수, 클릭, 휠, 이동 거리 등 16개. 입력 내용은 쓰지 않음.
- 전처리: 무활동 분 제외, 결측은 중앙값 대체, 표준화.
- 모델: 로지스틱 회귀, Isotonic 확률 보정.
- 출력: 스트레스 지수 0~100. 50 이상 관찰, 63 이상 개입.
- 평가: 참가자를 통째로 나누는 5겹 교차검증. 결측 대체와 표준화는 폴드 안에서 계산.
- 추론 함수는 계수를 내장해 표준 라이브러리만으로 동작함(`keyboard_model/predict.py`).

### 2. 수집 데이터로 다시 검증

- 분 단위 중복 제거: 같은 사용자, 같은 분에 여러 번 전송된 행이 44.2%였음. 활동량이 가장 큰 1건만 남김.
- 집계 단위를 직전 1분에서 직전 30분 평균으로 바꿈.
- 개인화: 개인 평균 쪽으로 중심을 옮기는 shrinkage, `w = n / (n + k)`.
- 라벨: 무작위·과부하 트리거 팝업에 15분 안에 응답한 것만 사용.
- 평가: 한 사람씩 빼고 학습하는 LOSO.

### 3. PPG/HRV 모델

- 입력: 손가락 PPG 원파형과 샘플링 주파수.
- 신호 처리: 0.5~4Hz 대역 통과, 품질 확인, 피크 검출, RR 간격 계산, 이상 박동 보간.
- 피처: 평균 심박, RMSSD, SDNN, pNN50. 60초 창, 개인 기준선 대비 z-score.
- 모델: 로지스틱 회귀(클래스 가중).
- 출력: 점수 0~100. 38.5 미만 낮음, 65.7 이상 높음, 사이는 관찰.
- 평가: LOSO. 신뢰구간은 사람 단위 부트스트랩.

### 4. 두 모델의 결합

- 키보드·마우스 모델이 상시로 선별하고, 알림에 사용자가 응답하면 PPG 측정으로 확인하는 2단계 구조.
- 행동, 자가보고, HRV 세 가지를 같은 사용자 ID로 이어 서로 맞는지 보는 것이 목표였음.
- 두 모델과 개인화 코드를 각각 만들어 서비스에 넣는 데까지 진행함. PPG 실측이 모이지 않아 결합 검증은 하지 못함(아래 한계).

## 결과

### 키보드·마우스, 공개 데이터 (SWELL-KW, 25명)

| 항목 | 값 |
|---|---|
| 사람 단위 교차검증 AUC | 0.63 |
| Nested CV AUC | 0.628 |
| 무작위 분할 AUC (누수 대조) | 0.657. 사람 단위 0.621과 DeLong z = -9.50, p < 0.0001 |
| 무활동 구간을 넣었을 때 | 0.71. 자리 비움을 맞힌 값이 섞여 대표값으로 쓰지 않음 |
| 자가보고 스트레스를 정답으로 둘 때 | 0.482 |

- 0.63과 0.621의 차이는 무활동 기준(분당 입력 10회 이상 / 1회 이상) 차이임.

### 키보드·마우스, 수집 데이터 (31명, 라벨 약 157건)

| 단계 | LOSO AUC |
|---|---|
| 직전 1분 창 | 0.48 |
| 직전 30분 평균 | 0.55 |
| 30분 평균 + 개인화 | 0.62 (0.619, Nested CV 0.607) |

- 같은 조건에서 개인화 없이 0.570, 개인화 후 0.619.
- 순열검정 p = 0.10으로 통계적 유의성에는 미치지 못함. 공개 데이터 결과와 방향이 같다는 정도로 해석함.
- 부트스트랩 2,000회로 다시 계산한 값은 0.612, 95% CI 0.525~0.698 (n=178). 라벨 182건 누적 기준으로는 0.585.
- 과부하 트리거만 빼고 무작위 트리거 응답만으로 계산해도 0.589.
- 타이핑 간격 등 원시 이벤트 파생변수 37개를 추가해 봤으나 학습 0.787, LOSO 0.476으로 과적합이었고 순열검정 p는 약 0.90. 전부 뺌.
- 시간대별 활동량과 "스트레스 예" 응답 비율의 상관은 r = -0.08. 바쁜 시간과 스트레스를 느끼는 시간이 일치하지 않음.

### PPG/HRV, 공개 데이터 (MAUS, 22명)

| 항목 | 값 |
|---|---|
| LOSO AUC (4피처, 60초, 757창) | 0.722. 사람 단위 95% CI 0.645~0.797 |
| LOSO AUC (4피처, 30초, 1508창) | 0.712 |
| 평균 심박 추가 효과 | +0.065. 95% CI +0.005~+0.121 |
| 0/2/3-back 3단계 분류 | macro-F1 0.36. 구분되지 않아 2단계로 감 |

- 위 수치는 분석 당시 기록한 값임. 어떤 값이 이 저장소 코드로 다시 계산되는지는 [docs/04_reproducibility.md](docs/04_reproducibility.md)에 구분해 둠.
- 선택마다의 근거는 [docs/03_decision_log.md](docs/03_decision_log.md)에 있음.

## 한계

- PPG/HRV 모델은 만들어서 서비스에 넣었지만, 팀 내부 사정으로 PPG 실측 데이터를 모으지 못함. 그래서 이 모델은 공개 데이터(MAUS)로만 검증했고, 키보드 판정을 HRV로 교차검증하는 작업도 하지 못함.
- PPG 모델은 256Hz 접촉식 센서 데이터 기준임. 폰 카메라 30fps 측정에 그대로 맞는지 확인하지 못했고, 판정 경계(38.5, 65.7)도 실측으로 다시 정해야 함.
- 수집 데이터의 키보드·마우스 결과(0.62)는 31명 기준이라 통계적으로 유의하지 않음.
- 테스터가 한 집단에서 모집되어 코딩 작업과 영문 입력 비중이 높음. 일반 사무직을 대표한다고 볼 수 없음.
- 팝업 질문은 "스트레스를 받았는지"이고 모델이 재는 것은 업무가 몰리는 정도임. 둘은 같은 것이 아님.
- 확률 수준에서 두 모델을 합치는 결합 모델은 만들지 않음.
- 진단 도구가 아님.

## 기술 스택

- Python, NumPy, SciPy, pandas, scikit-learn, joblib, matplotlib

## 폴더 구조

```
keyboard_model/
  predict.py                  추론 함수 (계수 내장, 표준 라이브러리만 사용)
  model_v1.json               계수, 표준화 값, 보정 값
  validation_samples.json     추론 검산용 예시 입력과 기대값
  preprocess.py               분 단위 중복 제거, 30분 집계, 자가보고 유효성
  personalize.py              shrinkage 개인화
  train/train_v1_model.py     SWELL-KW 학습, 계수 JSON 저장
  eval/methodology_validation.py   보정, Nested CV, DeLong 검정
  field_validation/           수집 데이터 분석 (EDA, 집단 비교, 순열검정, 단계별 AUC)
ppg_hrv/
  ppg_pipeline.py             PPG 파형 -> HRV
  stress_judge.py             HRV -> 점수와 판정, 개인 기준선 블렌드
  ppg_stress_base_maus_60s.pkl     모델 번들 (계수, 집단 통계, 컷)
  train/                      MAUS 재처리, 모델 번들 생성
  eval/                       LOSO, 창 길이와 피처 비교, 부트스트랩, 판정 경계
demo/run_demo.py              합성 입력으로 두 모델 실행
tests/check_reproducible.py   재실행 결과 일치 확인
docs/                         데이터와 변수, 데이터 점검, 판단 기록, 재실행
```

## 실행

```bash
pip install -r requirements.txt

python demo/run_demo.py               # 합성 입력으로 두 모델 실행
python tests/check_reproducible.py    # 재실행 결과가 기대값과 같은지 확인
```

- 학습과 평가를 다시 돌리려면 SWELL-KW와 MAUS를 각 배포처에서 받아야 함. 순서는 [docs/04_reproducibility.md](docs/04_reproducibility.md)에 있음.
- `keyboard_model/field_validation/`은 수집 데이터가 있어야 실행됨. 데이터를 공개하지 않으므로 코드만 둠.
