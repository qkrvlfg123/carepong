# 판단 기록

분석 중 선택이 필요했던 지점과 그때의 근거를 순서대로 적음.
수치 옆의 (코드)는 이 저장소 스크립트로 다시 계산할 수 있는 값, (기록)은 분석 당시 보고서에 남긴 값임.

## 키보드·마우스 모델

### K1. 피처를 16개로 정함

- 선택: SWELL-KW 컴퓨터 상호작용 18개 중 앱 전환 2개를 빼고 16개 사용.
- 근거: 앱 전환을 세려면 창 제목에 접근해야 함. 제외해도 AUC가 같았음(무활동 필터 전 0.714). (기록)
- 버린 안: 표정, 자세 피처. 상시 촬영과 3D 센서가 필요함.

### K2. 16개를 더 줄이지 않음

- 선택: 변수 선택 없이 전부 사용.
- 근거: 키보드만 0.578, 마우스만 0.579, 합치면 0.634. 유의한 11개만 쓰면 0.617. (기록)
- 버린 안: 전체 데이터로 중요도를 본 뒤 상위 변수만 남기는 방식. 평가 데이터를 보고 변수를 고르는 셈이라 누수가 됨.

### K3. 무활동 구간을 평가에서 뺌

- 선택: 키와 마우스 입력이 모두 0인 분 제외.
- 근거: 제외한 477분 중 409분이 휴식. 제외 전 0.71은 자리 비움을 맞힌 값이 섞인 수치임. (기록)
- 결과: 대표 성능을 0.63으로 보고함.

### K4. 사람 단위로 분할함

- 선택: `StratifiedGroupKFold`로 참가자를 통째로 나눔. 결측 대체와 표준화도 폴드 안에서 계산.
- 확인: 무작위 분할 0.657, 사람 단위 0.621. DeLong 검정 z = -9.50, p < 0.0001. (코드: `methodology_validation.py`, 수치는 기록)
- 해석: 무작위 분할의 높은 값은 같은 사람의 분이 양쪽에 들어가서 생긴 것임. 사람 단위 값을 보고함.

### K5. 로지스틱 회귀를 씀

- 선택: 로지스틱 회귀.
- 근거: 8종 비교에서 모두 0.60~0.63. 로지스틱 0.634, XGBoost 0.604. (기록)
- 부가 근거: 계수 16개와 절편만 있으면 추론이 되어 표준 라이브러리만으로 구현할 수 있음(`predict.py`).
- 확인: Nested CV 0.628로 단일 CV 0.634와 차이가 작음. 튜닝으로 성능이 올라간 것이 아님. (코드, 수치는 기록)

### K6. 확률을 Isotonic으로 보정함

- 선택: 학습, 보정, 평가를 사람 단위로 나눠 보정.
- 확인: Brier 0.217에서 0.220. 보정 전후 차이가 거의 없음. (코드, 수치는 기록)

### K7. 타이밍 파생변수를 폐기함

- 시도: 타이핑 리듬, 멈춤, 버스트 등 9개 파생변수 추가. 처음에 0.625로 오름.
- 발견: 엑셀(현지 시각)과 원시 로그(UTC)가 2시간 어긋나 병합이 대부분 실패했고 약 70%가 결측이었음. 모델이 결측 패턴을 학습한 결과였음.
- 결과: 시간대를 맞춘 뒤 파생변수만으로 0.505. 폐기함. (기록)

### K8. 측정 대상을 "업무 부하"로 한정함

- 확인: 자가보고 스트레스를 라벨로 두면 AUC 0.482. 지수와 자가보고 상관 r = 0.009. (기록)
- 판단: 키보드·마우스로 체감 스트레스를 맞힌다고 말할 수 없음. 서비스 문구도 진단이 아니라 "평소보다 몰리는 구간 알림"으로 정함.

### K9. 개입 컷을 63으로 정함

- 선택: Youden's J가 최대인 63.
- 근거: 50은 헛경보가 54%, 75는 헛경보 2%이지만 약 79%를 놓침. (기록)

### K10. 개인화는 shrinkage로 함

- 시도: SWELL 안에서 개인 중립 구간 기준 정규화. 0.62로 오히려 내려감. 한 사람당 3시간이라 기준 데이터가 부족했음. (기록)
- 시도: 절대값 16개에 개인 편차 16개를 더한 32피처. 사람 단위 0.693, 무작위 0.716. (기록)
- 선택: 서비스에서는 `w = n / (n + k)`로 개인 평균 비중을 서서히 올림. 데이터가 적을 때 개인 평균이 불안정한 문제를 피하기 위함.
- 확인: 수집 데이터에서 개인화 없이 0.570, 개인화 후 0.619. (기록, F3)

## 수집 데이터 검증 (키보드·마우스)

대상은 서비스 테스터 31명, 유효 라벨 약 157건. 코드는 `keyboard_model/field_validation/`에 있고 데이터는 공개하지 않음.

### F1. 분 단위 중복을 제거함

- 발견: 사용자와 분 단위 시각으로 묶어 세어 보니 같은 분에 여러 건이 들어온 행이 전체의 44.2%였음. 한 분에 최대 355건. 클라이언트 다중 전송 문제였음.
- 선택: 같은 사용자, 같은 분은 활동량이 가장 큰 1건만 남김. 194,484행에서 108,566행.
- 근거: 그대로 두면 같은 창이 반복되어 성능이 부풀고, 시간대 분포도 왜곡됨(15시 창 수 13,294가 정리 후 3,206).

### F2. 계정 하나와 점검용 세션을 뺌

- 선택: 단일 세션이 전체 행의 55%를 차지하고 평균 타이핑이 4.2로 비정상인 계정 1개 제외. 자동 점검용 세션 28개와 그 라벨 14건 제외.
- 선택: 기록이 100개 미만인 사용자는 개인 기준선을 믿을 수 없어 개인화 분석에서 제외.

### F3. 집계 단위를 30분으로 바꾸고 개인화를 넣음

- 결과: 직전 1분 0.48, 직전 30분 평균 0.55, 개인화 추가 0.62(LOSO 0.619, Nested CV 0.607). (기록)
- 근거: 과부하 알람 규칙이 30분 단위이고, 1분 창은 변동이 큼.
- 주의: 순열검정 p = 0.10. 31명으로는 유의하다고 말할 수 없음. 부트스트랩 재계산 0.612(95% CI 0.525~0.698), 라벨 182건 누적 기준 0.585.

### F4. 1분 창 성능은 재현 대상에서 뺌

- 발견: 과부하(spike) 트리거는 활동이 많을 때 팝업을 띄움. 그래서 팝업이 뜬 1분 창의 활동 피처가 라벨을 일부 설명함. 트리거별 "예" 비율이 spike 약 0.62, random 약 0.51.
- 확인: 1분 창 AUC는 전체 0.629, 무작위 트리거만 0.497. 30분 평균과 개인화 단계는 전체 0.612, 무작위 트리거만 0.589. 1분 창의 높은 값은 트리거에서 온 것임. (기록)
- 선택: `verify_staged_auc.py`는 30분 집계와 개인화 단계만 계산함.

### F5. 아침 체크인 라벨을 예측 대상에서 뺌

- 선택: `morning` 트리거 응답 123건은 그날의 출발 상태를 묻는 것이라 직전 행동과 대응하지 않음. 예측 대상에서 빼고 개인 기준선 계산에만 씀.
- 선택: 응답 지연이 15분을 넘거나 닫기·무시·무응답인 건은 라벨로 쓰지 않음.

### F6. 타이핑 리듬 파생변수 37개를 폐기함

- 시도: 키 입력 간격의 분포, 엔트로피, 자기상관, 버스트, 멈춤 등 37개를 추가.
- 결과: 학습 AUC 0.787, LOSO 0.476. 사용자 내 라벨을 섞는 순열검정에서 관측 변화량 -0.047, p 약 0.90. (기록)
- 판단: 표본이 작아 생긴 과적합. SWELL에서도 0.505였음(K7). 신호는 간격이 아니라 입력량에 있다고 봄.

## PPG/HRV 모델

### P1. 생체 신호 모델을 따로 둠

- 배경: SWELL에 들어 있는 HRV를 키보드 모델에 붙여 봤으나 0.629에서 0.643. 결측이 53%였음. (기록)
- 선택: 손가락 PPG 전용 공개 데이터(MAUS)로 별도 모델을 만듦.

### P2. 창 길이를 60초로 함

- 비교: 30초 LOSO AUC 0.712, 60초 0.722. (코드: `maus_feature_eval.py`, 수치는 기록)
- 선택: 배포 모델은 60초 창으로 정함.
- 주의: 60초에서는 주파수 영역 지표를 믿을 수 없어 입력에서 뺌.

### P3. 평균 심박을 피처에 넣음

- 비교: 4피처(`mean_hr` 포함)와 3피처의 차이를 사람 단위 부트스트랩 1000회로 검정.
- 결과: +0.065, 95% CI +0.005~+0.121, 1000회 중 98.2%에서 개선. (코드: `paired_diff.py`, 수치는 기록)

### P4. LOSO로만 평가함

- 선택: 한 사람씩 빼고 학습하는 방식.
- 근거: 창 단위로 나누면 같은 사람의 창이 양쪽에 들어감.
- 보고: AUC 0.722. 사람 단위 95% CI 0.645~0.797, 창 단위 0.683~0.760. 두 구간을 구분해 적음.

### P5. 3단계 난이도 분류를 접음

- 시도: 0-back, 2-back, 3-back 3클래스 분류.
- 결과: macro-F1 0.36. 2-back과 3-back이 구분되지 않음. (코드: `maus_3class_loso.py`, 수치는 기록)
- 선택: 저부하와 고부하 2단계 모델로 감.

### P6. 판정에 관찰 구간을 둠

- 선택: 점수 38.5 미만은 낮음, 65.7 이상은 높음, 사이는 관찰.
- 근거: 컷 하나로 나누면 경계 근처 오판이 많음. 민감도와 특이도 0.85 지점을 각각 경계로 씀. (코드: `hrv_band_cutoff.py`)
- 주의: 경계는 MAUS 기준임. 폰 카메라 실측으로 다시 정해야 함.

### P7. 아티팩트 박동은 보간함

- 처음에는 이상 박동을 삭제했는데 RMSSD가 생리 범위를 넘게 나왔음. 삭제하면 양옆 박동이 붙어 차이가 커지기 때문임.
- 선택: 삭제 대신 보간. 표시된 박동이 50%를 넘으면 창 전체를 버림.

## 결합 구조

### M1. 두 모델을 순서대로 씀

- 선택: 키보드·마우스 모델이 상시로 선별하고, 알림이 뜨면 사용자가 PPG를 60초 측정해 확인하는 2단계 구조.
- 근거: 키보드·마우스는 추가 기기 없이 항상 돌아가지만 신호가 약함(0.63). PPG는 신호가 더 강하지만(0.72) 측정 행동이 필요함.
- 설계: 알림에 "예"라고 답하든 "아니오"라고 답하든 PPG 측정으로 이어지게 함. 행동은 과부하인데 본인은 아니라고 한 경우를 HRV로 가르기 위함.
- 상태: 두 모델과 개인화 코드를 각각 만들어 서비스에 넣는 데까지 함. 팀 내부 사정으로 PPG 실측이 모이지 않아, 같은 사용자의 키보드 판정과 PPG 판정이 얼마나 일치하는지는 확인하지 못함. 확률 수준에서 합치는 결합 모델은 만들지 않음.
