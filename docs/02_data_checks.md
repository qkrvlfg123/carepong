# 결측, 이상값, 편향 점검

수치의 출처는 두 가지임.

- (코드) 이 저장소의 스크립트로 다시 계산할 수 있는 값.
- (기록) 분석 당시 보고서에 남긴 값. 계산 코드는 이 저장소에 없음.

## 1. 키보드·마우스 (SWELL-KW)

### 결측

- 16피처의 결측은 약 1%. 각 참가자의 첫 분처럼 직전 기록이 없는 구간에서 생김. (기록)
- 처리: 학습 데이터의 중앙값으로 대체함.
  - 행을 지우지 않은 이유: 서비스에서는 일부 값이 비어도 판정을 내야 함.
  - 평균 대신 중앙값을 쓴 이유: 분포가 오른쪽으로 치우쳐 있고 극단값이 있음(이동 거리 최대 81,098).
- 대체에 쓴 중앙값은 `model_v1.json`의 `impute_median`에 있음. (코드)
- 대체는 파이프라인 안에서 폴드마다 따로 계산함. 평가 폴드의 값이 대체값에 섞이지 않게 하기 위함. (코드, `methodology_validation.py`)

### 이상값

- IQR 1.5배 기준 이상값 비율이 높게 나온 변수: 더블클릭 20.3%, 방향키 17.5%, 우클릭 14.4%. (기록)
- 판단: 이상값으로 처리하지 않음. 이 동작들은 대부분의 분에서 0이라, 정상적인 몇 번의 입력이 IQR 기준에 걸린 것임.
- 스케일 차이가 큰 변수(`SnMouseDistance`, `ErrorKeyRatio`)가 있어 전 변수를 표준화함.

### 무활동 구간

- 키와 마우스 입력이 모두 0인 분을 평가에서 제외함.
- 제외한 477분 중 409분이 휴식 조건이었음. (기록)
- 제외 전 AUC 0.71, 제외 후 0.63. 0.71은 자리 비움을 쉽게 맞힌 값이 섞인 수치라 대표값으로 쓰지 않음. (기록)
- 활동 하한선을 0~30으로 바꿔 본 결과, 10까지는 주로 휴식 구간이 빠지고 15부터 업무 구간이 빠지기 시작함. (기록)

### 다중공선성

- `SnKeyStrokes`는 하위 키 종류의 합이라 VIF가 무한대로 나옴. (기록)
- 목적이 계수 해석이 아니라 예측이라 변수를 빼지 않음.

### 편향과 대표성

- 표본: 25명, 한 사람당 약 3시간, 실험실 통제 과제.
- 라벨은 실험 조건임. 참가자 자가보고 스트레스를 라벨로 두면 AUC 0.482로 구분하지 못함. 지수와 자가보고 점수의 상관은 r = 0.009. (기록)
  - 따라서 이 모델이 재는 것은 "업무가 몰리는 상황"이며 체감 스트레스가 아님.
- 조건이 블록 단위로 배치되어 있어 시간 순서와 조건이 섞여 있음.
- 영문 입력 기준 데이터임. 한글은 조합형이라 같은 내용에도 키 입력 수가 달라, 절대값 기준 판정이 한글 사용자에게 그대로 맞지 않을 수 있음.
- 같은 사람의 분이 학습과 평가에 함께 들어가면 성능이 높게 나옴. 무작위 분할 AUC 0.657, 사람 단위 분할 0.621, DeLong 검정 z = -9.50, p < 0.0001. (코드로 재계산 가능, 수치는 기록)

## 2. 손가락 PPG (MAUS)

### 결측과 품질 미달 창

- 창 단위로 품질을 확인하고 기준에 못 미치면 버림. (코드, `ppg_pipeline.py`, `maus_reprocess.py`)
  - 심박 대역(0.7~3.5Hz) 파워 비율 0.4 이하
  - 스펙트럼으로 추정한 심박이 40~180 bpm 밖
  - 보정 후 박동 수 5개 미만
  - 아티팩트로 표시된 박동이 50%를 넘음
- 남은 창: 60초 기준 757창, 30초 기준 1508창, 22명. (기록)
- 폰 카메라 입력용 `process_ppg`는 기준을 완화해 둠(왜도 -1.5 초과, 대역 비율 0.2 초과). 접촉식 센서 기준을 그대로 쓰면 폰 측정이 지나치게 많이 거절되기 때문임.

### 이상값

- RR 간격이 300~1500ms 밖이면 아티팩트로 표시함.
- 국소 중앙값에서 25% 넘게 벗어난 박동을 2회 반복해 찾음.
- 표시된 박동은 지우지 않고 보간함. 지우면 양옆 박동이 붙어 RMSSD가 커짐.
- MAUS 손가락 PPG는 파형이 뒤집혀 있어 -1을 곱해 씀.

### 편향과 대표성

- 표본: 22명, 실험실 N-back 과제. 일상 업무 스트레스와 같다고 볼 근거는 없음.
- 256Hz 접촉식 센서 데이터임. 서비스 입력은 폰 카메라 30fps라 신호 품질이 다름.
- 라벨 불균형은 `class_weight="balanced"`로 다룸.
- 평가를 창 단위로 하면 같은 사람의 창이 양쪽에 들어감. 그래서 LOSO(한 사람씩 빼고 학습)로만 평가하고, 신뢰구간도 사람 단위 부트스트랩으로 따로 냄.
- 평가에서 개인 z-score는 그 사람의 전체 창 평균과 표준편차로 계산함. 라벨은 쓰지 않지만 평가 대상의 분포 정보가 들어감. 서비스에서는 안정 상태 측정 몇 건으로 기준선을 잡으므로, 보고한 AUC가 서비스 성능과 같다고 볼 수 없음.
- 2-back과 3-back은 HRV로 구분되지 않음(3클래스 macro-F1 0.36). 그래서 저부하와 고부하 2단계로만 판정함.

## 3. 서비스 수집 데이터

데이터 자체는 공개하지 않음. 점검 규칙은 `keyboard_model/preprocess.py`, 분석 코드는 `keyboard_model/field_validation/`에 있음. 수치는 전부 (기록).

### 데이터 흐름

| 단계 | 행 수 | 설명 |
|---|---|---|
| 수집 원본 | 194,484 | 1분 창 |
| 분 단위 중복 제거 | 108,566 | 44.2% 제거 |
| 활동 창 | 21,027 | 무활동 창 제외. 중복 제거분의 19.4% |
| 유효 라벨 | 157건, 31명 | random·spike 트리거, 응답 완료, 15분 이내. 2026-11-02~03 재추출 기준 |
| 개인 기준선 산출 | 19명 | 기록 100개 이상인 사용자 |

### 결측과 중복

- 같은 사용자, 같은 분에 여러 건이 전송된 행이 44.2%였음. 한 분에 최대 355건. 활동량이 가장 큰 1건만 남김.
- 중복을 그대로 둔 시간대 분포에서는 15시 창 수가 13,294로 튀었고, 그중 70%가 계정 하나의 다중 전송이었음. 정리 후 3,206.
- 무활동 창이 중복 제거분의 약 80%. 자리 비움이라 판정 대상이 아님.

### 이상값

- 계정 1개 제외: 단일 세션이 전체 행의 55%, 평균 타이핑 4.2. 교육장 PC에서 나온 기록임.
- 자동 점검용 세션 28개와 라벨 14건 제외.
- 더블클릭처럼 대부분 0인 변수는 SWELL과 같은 이유로 이상값 처리하지 않음.

### 라벨

- 팝업 표시 후 15분 안에 응답한 것만 라벨로 씀. 늦은 응답은 회상 편향이 생김.
- 응답 상태를 4종(answered, pending, dismissed, ignored)으로 나눠 응답률과 이탈률을 같이 봄. 응답한 사람만 보면 무응답 편향을 알 수 없음.
- 아침 체크인 응답 123건은 직전 행동과 대응하지 않아 예측 대상에서 뺌.
- 과부하 트리거 팝업은 활동이 많을 때 뜸. 팝업이 뜬 1분 창으로 평가하면 활동 피처가 라벨을 일부 설명하게 되어 성능이 높게 나옴. 그래서 1분 창 평가값은 대표값으로 쓰지 않음.

### 편향과 대표성

- 테스터가 같은 교육과정 수강생임. 코딩 작업과 영문 입력 비중이 높고 일과 시간이 비슷함(활동이 9시~18시 30분에 몰리고 13시에 가장 낮음).
- 사용자별 평소 타이핑량 차이가 큼. 절대값 기준 판정은 많이 치는 사람을 계속 과부하로 봄. 개인화를 넣은 이유임.
- 31명으로는 통계적 유의성을 확보하지 못함(순열검정 p = 0.10).
- 자가보고는 "스트레스를 받았는지"를 묻고 모델은 업무가 몰리는 정도를 잼. 시간대별 활동량과 "예" 비율의 상관은 r = -0.08.
- 손가락 PPG는 분석할 만큼 모이지 않아 점검 대상이 없음.
